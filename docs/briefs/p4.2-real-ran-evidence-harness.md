# Codex brief — P4.2 real-RAN evidence harness

> Hand this to Codex. It builds the missing bridge between "a dev points real RAN
> at QCore" and "we learned something we can ship." Today a real gNB/UE run leaves
> **no structured artifact** — just anecdotes. This makes every external run produce
> a reproducible evidence bundle and a one-line Findings-log entry.

## Read first (every session)
- `CLAUDE.md` (evidence rules, verification protocol, build principles).
- `docs/experience-charter.md` §11 ("Not Now") — resist conformance-matrix scope creep.
- `docs/next-phases-plan.md` P4.2 — this brief is that task.
- `docs/ueransim-compat.md` — the existing Findings/Verified-in-Replay format to mirror.

## Why
T10 is validated **only for the bundled UERANSIM Docker/cloud-Linux profile**. The
roadmap's P4.2 is "per-target real-RAN replay — one replay + evidence per target,"
and the explicit rule is **never generalize a single target into a conformance
claim**. To do that honestly we need a repeatable capture path that records exactly
what happened, so a real gNB run is evidence, not a story.

## Goal
A scripted, reproducible **evidence harness** that, for one RAN target, captures:
1. **TTFC** — time from core-up to gNB/core connected (NGAP NG Setup complete).
2. The **journey trace** for the attach (from the real `/api/events/stream` SSE
   feed / collector), saved as JSON.
3. On failure: the **diagnostic report** QCore produced (cause + both-sided fix) and
   the **`/api/ran-config/reconcile`** result, plus **TTRC** (time to that report).
4. A distilled **Findings-log entry** appended to a per-target compat doc.

## What to build
- **`scripts/ci/real-ran-capture.sh`** — parameterized by a target descriptor
  (env vars or a small YAML: `TARGET_NAME`, `MODE=5g|4g`, `RAN_KIND=ueransim|srsran|real-gnb|real-enb`,
  optional gNB/UE config paths). It brings the core up (`make up-5g` / `make up`),
  waits for the RAN to attach (or for the operator to point a real gNB at the
  advertised AMF NGAP endpoint), polls the existing dashboard/collector APIs, and
  writes a bundle under **`artifacts/real-ran/<target>-<UTC-date>/`** (already
  gitignored via the `artifacts/` rule):
  - `trace.json` — the captured journey events.
  - `diagnosis.json` — the diagnostic report if the attach failed (else omitted).
  - `reconcile.json` — output of `POST /api/ran-config/reconcile` when configs are available.
  - `timings.json` — `{ ttfc_s, ttrc_s, result: "pass"|"fail", failed_step, cause }`.
  - `summary.md` — human-readable one-pager generated from the above.
  - Reuse the polling/endpoint patterns already in `scripts/ci/ueransim-sqn-resync.sh`
    and `scripts/ci/ueransim-suci-profile-a.sh`; do **not** invent new core APIs —
    verify each endpoint exists (`rg` in `pkg/dashboard`) before calling it.
- **`docs/real-ran-compat.md`** (new) — a Findings log, one section per target,
  mirroring the `## Verified In Replay` / `## Scope And Remaining Caveats` shape of
  `docs/ueransim-compat.md`. Each entry states: target + version, host, MODE, result,
  TTFC/TTRC, evidence path or CI run ID, and an explicit **scope caveat** ("this is
  one target; not a conformance claim"). Keep UERANSIM-bundled results in
  `ueransim-compat.md`; non-bundled / real hardware goes here.
- **Self-test wiring:** the harness must produce a real bundle from the **bundled
  UERANSIM profile** run (the one target we can run in CI) as its own proof. Add an
  optional `ueransim-interop.yml` step (or a sibling job) that runs
  `real-ran-capture.sh` with `RAN_KIND=ueransim` and uploads the artifact — gated so
  it never weakens the existing `T10 DATA PLANE PASS` / `SQN RESYNC` / `SUCI` gates.

## Out of scope (charter §11)
No HA/scale, no new protocol features, no per-baseband matrix, no auto-grading a
target as "supported." The harness records; humans interpret. One target at a time.

## Acceptance (trust rule — "code exists" ≠ done)
- `scripts/ci/real-ran-capture.sh` runs against the bundled UERANSIM 5G profile on a
  Linux host and emits a complete bundle (`trace.json` non-empty, `timings.json` with
  a real `ttfc_s`, `summary.md` readable).
- A forced failure (e.g. `inject wrong_ki`) produces `diagnosis.json` with a non-empty
  cause and a `ttrc_s`.
- `docs/real-ran-compat.md` has the first entry (the UERANSIM self-test), with the
  scope caveat present.
- Full **`go build ./... && go vet ./... && go test ./...`** green in `golang:1.23`
  Docker (no host Go), and the dashboard `tsc --noEmit` + `vite build` clean if any
  TS/UI touched. Cite the CI run ID for the harness job.

## Verify / guardrails (non-negotiable)
- Build/test **only** in Docker:
  `docker run --rm -v "$PWD":/src -w /src -v qcore-gomod:/go/pkg/mod golang:1.23 sh -c "go build ./... && go vet ./... && go test ./..."`.
- Do all work in an **isolated git worktree** — never share the live checkout.
- **New commits only**; never amend, never force-push, never touch git config, never
  commit secrets (real subscriber Ki/OPc must never land in `artifacts/` that gets
  shared — scrub before writing).
- Bring the branch fully up to date with `main`, open a PR, and let CI prove it.
