# P2.2 — RAN/device config reconciliation (E1) — Codex build brief

> Self-contained brief for the next unit. Read `docs/experience-charter.md` (§9 AI,
> §7 Golden Path), `CLAUDE.md`, and `docs/next-phases-plan.md` (P2.2) first. This brief
> expands the P2.2 entry; it does not override the charter.

## Mission
Most real QCore failures are **config mismatches** — PLMN, TAC, S-NSSAI, serving-network
name, Ki/OPc, SUCI scheme — exactly the class of bug the whole T10 effort kept hitting.
Build the feature that takes a user's **RAN/UE config** (a UERANSIM `gnb.yaml`/`ue.yaml`,
or pasted field values) and **diffs it against the running core's config**, surfacing the
exact mismatched field(s) **and the fix — before, and without needing, a live attach.**
This is the single highest-value remaining diagnostic feature (charter §9 / Golden Path
Step 4 / `docs/v1-gap-closure-plan.md` §5 E1).

## Hard guardrails (read first)
- **No Go toolchain on host** — every Go build/vet/test runs in Docker:
  ```bash
  docker run --rm -v "$PWD":/src -w /src -v qcore-gomod:/go/pkg/mod golang:1.23 \
    sh -c "go build ./... && go vet ./... && go test -race ./..."
  ```
- **Frontend:** `cd pkg/dashboard/web && npx tsc --noEmit && npm run build` must pass.
- **Trust rule:** done only when build + vet + tests pass. "Code exists" ≠ "shipped." Mark
  a doc row ✅ only after green tests **and** a dashboard runtime check.
- **Scope discipline (charter §11):** this is config *reconciliation*, NOT new protocol
  features. Do **not** add SUCI Profile A/B, GUTI re-registration, or new NGAP/PFCP here.
  If a mismatch can only be resolved by a protocol change, **flag it** — don't build it.
- **Branch:** `codex/e1-ran-reconciliation`. One PR. New commits only; never force-push.
- **Do not regress** the green `ueransim-interop` / `CI` gates on `main`.

## What already exists — REUSE, don't rebuild
1. **`pkg/diag/ngsetup.go` → `DiagnoseNGSetup(req, cfg AMFConfig)`** already detects
   `plmn_mismatch`, `tac_mismatch`, `slice_mismatch` from a **live** NGSetupRequest vs the
   AMF config, each with a machine tag + human `Fix` string. **This is your reference
   logic and field set.** P2.2 generalizes it to a **static, pre-attach** config-vs-config
   diff (no live request). Reuse the same Cause tags + Fix phrasing where they overlap.
2. **`pkg/dashboard/ran.go` → `RANConfig` + `handleRANConfig` (`GET /api/ran-config`)**,
   plus `ueransimGNBSnippet` / `srsRANENBSnippet` / `open5gsENBSnippet`. That view is
   **core → RAN** ("configure your RAN to match the core"). P2.2 is the **inverse**:
   RAN config → diff vs core. Add the new handler next to `handleRANConfig`.
3. **Core config:** `pkg/config/config.go` — `amf.plmn` (`"00101"`), `amf.tac` (uint16),
   `amf.serving_network_name`, S-NSSAI/SST; `mme.plmn`/`mme.tac` for 4G. `pkg/config/
   validate.go` has `validatePLMN` / `validateTAI` — reuse for format checks.
4. **Subscriber Ki/OPc:** the subscriber store behind `/api/subscribers` holds IMSI/Ki/OPc
   for reconciling a UE's `key`/`op`/`opc` against the provisioned subscriber. (Dev tool:
   comparing is fine; avoid logging secrets.)
5. **Diagnostic surface:** the `pkg/diag` Cause/Fix pattern and `pkg/ai/catalog.go`.
   Reconciliation findings should produce the same Cause/Fix shape so the dashboard renders
   them with the existing diagnostic card styling.

## The unit of work
1. **Inspect the five items above first** so you reuse the existing diff logic + field names.
2. **Reconciliation core** (new, e.g. `pkg/diag/reconcile.go` or a small `pkg/reconcile`):
   - Input: a normalized RAN/UE config — PLMN, TAC, S-NSSAI (SST + optional SD),
     serving-network name; UE IMSI, Ki, OPc/OP, SUCI protection scheme.
   - Compare against the core config + (for the UE) the provisioned subscriber.
   - Output: `[]Mismatch{ Field, RANValue, CoreValue, Cause, Fix, Severity }`, plus an
     all-match "OK" result.
   - Cover at least: PLMN, TAC, S-NSSAI (SST/SD), serving-network name, UE Ki, UE OPc/OP,
     and SUCI scheme (flag non-null-scheme as *"core supports null-scheme only today — see
     roadmap"*, do not implement Profile A/B).
3. **Input parser** (tolerant): accept the UERANSIM `gnb.yaml` + `ue.yaml` fields used by
   `deployments/docker/ueransim-config/*.yaml`, **and** a plain JSON of the same fields, so
   the UI can post pasted YAML or form values. Ignore unknown keys.
4. **Endpoint:** `POST /api/ran-config/reconcile` (register in `pkg/dashboard/server.go`
   beside `/ran-config`, handler in `pkg/dashboard/ran.go`). Body = RAN/UE config (YAML or
   JSON); response = the mismatch list (or OK). **No live attach.**
5. **Dashboard UI (minimal, scoped):** a "Check my RAN config" panel in the existing
   RAN-connect/hero area — paste `gnb.yaml`/`ue.yaml` → shows ✅ "matches the core" or the
   specific mismatched fields + fixes, using the existing diagnostic card styling. **No new
   tabs/routes** beyond this panel.

## Tests
- Go: table-driven tests for the reconciliation core — one case per mismatch type (PLMN,
  TAC, SST/SD, SNN, Ki, OPc, SUCI scheme), the all-match case, and YAML+JSON + malformed
  parsing. Mirror `pkg/diag/ngsetup_test.go` style.
- Endpoint test for `/api/ran-config/reconcile` (matched + mismatched).
- Frontend: `tsc --noEmit` clean; the panel renders.
- **Preserve all existing tests.**

## Acceptance / Definition of done
- A deliberately-mismatched gNB/UE config (e.g. PLMN `00102` vs core `00101`, or a wrong
  Ki) makes the API + dashboard report the **specific** mismatched field(s) + the fix,
  **before/without** a live attach. An all-match config returns "matches the core."
- `go build ./... && go vet ./... && go test -race ./...` green in `golang:1.23`; frontend
  `tsc` + `vite build` green; `make verify-fast` green.
- A dashboard runtime check: paste a mismatched UERANSIM `gnb.yaml` → the right field is
  flagged with a fix.
- Docs reconciled honestly: README status row, `docs/audit-v1.0.md` revision entry,
  `docs/next-phases-plan.md` P2.2 → done. Mark ✅ only after the above.

## Stop condition
Stop when **(A)** the reconcile endpoint + UI report mismatches correctly, tests are green,
and a dashboard runtime check passes — or **(B)** you hit a concrete blocker: document it
and the exact next step, and do **not** broaden into protocol features to work around it.
